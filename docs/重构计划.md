# FCK 项目重构计划（调整版）

## 一、项目背景

FCK是一个用Go语言开发的多功能文件系统命令行工具集，当前项目结构不符合qflag规范，需要进行重构以符合标准规范。

## 二、当前项目结构分析

### 2.1 现有结构
```
fck/
├── main.go                    # 程序入口点
├── commands/                  # 核心命令模块目录
│   ├── cmd.go                 # 命令调度主文件
│   ├── flags.go               # 全局标志配置
│   ├── check/                 # 文件完整性校验模块
│   ├── find/                  # 高级文件查找模块
│   ├── hash/                  # 文件哈希计算模块
│   │   ├── cmd_hash.go       # 主入口和流程控制 (146行)
│   │   ├── collectfiles.go   # 文件收集逻辑 (258行)
│   │   ├── hashtasks.go      # 并发哈希计算 (473行)
│   │   └── flags.go         # 命令行标志定义
│   ├── list/                  # 目录列表模块
│   ├── pack/                  # 文件打包模块
│   ├── preview/               # 压缩包预览模块
│   ├── size/                  # 文件大小统计模块
│   ├── unpack/                # 文件解包模块
│   ├── watch/                 # 命令监控模块
│   └── internal/              # 内部共享模块
│       ├── utils/            # 通用工具函数
│       └── types/             # 数据类型定义
```

### 2.2 存在的问题

1. **目录结构不符合规范**
   - 命令模块分散在多个子目录中
   - 缺少 `cmd/yourapp/` 标准入口目录
   - 缺少 `internal/cli/` 命令集中管理目录

2. **入口文件位置不规范**
   - main.go直接在根目录
   - 未遵循 `cmd/yourapp/main.go` 标准

3. **命令注册方式不统一**
   - 使用分散的初始化函数
   - 命令调度逻辑集中在cmd.go中

4. **文件组织不符合单文件原则**
   - 每个命令模块有多个文件（如hash有4个文件）
   - 业务逻辑和命令行接口混杂

5. **代码复杂度高**
   - 命令模块包含大量业务逻辑
   - 直接将业务逻辑迁移到CLI层不现实

## 三、重构目标

### 3.1 目标结构
```
fck/
├── cmd/
│   └── fck/                    # 程序入口
│       └── main.go             # 唯一入口：只调用 cli.Run()
├── internal/
│   ├── cli/                    # 命令行接口层（新增）
│   │   ├── root.go            # 根命令：help/usage
│   │   ├── check.go           # check命令的CLI接口
│   │   ├── find.go            # find命令的CLI接口
│   │   ├── hash.go            # hash命令的CLI接口
│   │   ├── list.go            # list命令的CLI接口
│   │   ├── pack.go            # pack命令的CLI接口
│   │   ├── preview.go         # preview命令的CLI接口
│   │   ├── size.go            # size命令的CLI接口
│   │   ├── unpack.go          # unpack命令的CLI接口
│   │   └── watch.go           # watch命令的CLI接口
│   ├── commands/               # 业务逻辑层（保持现有结构）
│   │   ├── check/             # 保持不变
│   │   ├── find/              # 保持不变
│   │   ├── hash/              # 保持不变
│   │   ├── list/              # 保持不变
│   │   ├── pack/              # 保持不变
│   │   ├── preview/           # 保持不变
│   │   ├── size/              # 保持不变
│   │   ├── unpack/            # 保持不变
│   │   ├── watch/             # 保持不变
│   │   ├── cmd.go             # 保留但简化
│   │   └── flags.go          # 移到cli层
│   ├── common/                # 工具函数（从commands/internal/common移动）
│   └── types/                 # 数据类型定义（从commands/internal/types移动）
├── go.mod
└── README.md
```

### 3.2 重构原则

1. **最小化风险**
   - 业务逻辑代码基本不变
   - 只添加新的CLI层
   - 逐步迁移，便于回滚

2. **符合规范**
   - CLI层遵循qflag规范
   - 入口文件极简
   - 命令集中管理

3. **保持功能完整性**
   - 所有现有功能保持不变
   - 命令行接口兼容
   - 测试可以复用

4. **便于维护**
   - CLI层和业务逻辑分离
   - 清晰的职责划分
   - 便于后续优化

## 四、重构步骤

### 4.1 目录结构调整
- 创建 `cmd/fck` 目录
- 创建 `internal/cli` 目录
- 移动 `commands/internal/common` → `internal/common`
- 移动 `commands/internal/types` → `internal/types`

### 4.2 业务逻辑层调整（最小改动）
- 将 `commands/` 重命名为 `internal/commands/`
- 移动 `commands/internal/` → `internal/commands/`（移除internal嵌套）
- 调整内部导入路径
- **保持所有业务逻辑代码不变**

### 4.3 创建CLI层（新增）

#### 4.3.1 创建根命令
- 创建 `internal/cli/root.go`
- 实现 `InitAndRun()` 函数
- 配置根命令选项和标志
- 注册所有子命令

#### 4.3.2 创建命令CLI接口
为每个命令创建 `internal/cli/{command}.go`：
- 只负责命令行参数解析
- 调用对应的业务逻辑函数
- 处理错误和输出

### 4.4 重构入口文件
- 创建 `cmd/fck/main.go`
- 极简实现：只调用 `cli.InitAndRun()`
- 错误处理和退出码

### 4.5 更新导入路径
- 更新所有文件的导入路径
- 确保模块间依赖正确
- 运行 `go mod tidy` 清理依赖

### 4.6 验证重构结果
- 构建项目
- 运行所有命令
- 验证功能完整性
- 测试边界情况

## 五、CLI层设计示例

### 5.1 根命令 (root.go)
```go
package cli

import (
    "fmt"
    
    "gitee.com/MM-Q/fck/internal/types"
    "gitee.com/MM-Q/qflag"
    "gitee.com/MM-Q/verman"
)

// InitAndRun 初始化并运行根命令
//
// 返回值:
//   - err: 初始化或运行命令时可能发生的错误
func InitAndRun() (err error) {
    defer func() {
        if r := recover(); r != nil {
            err = fmt.Errorf("panic recovered: %v", r)
        }
    }()

    // 配置根命令
    rootCmdOpts := &qflag.CmdOpts{
        Version:    verman.V.Version(),
        Desc:       "多功能文件处理工具集, 提供文件哈希计算、大小统计、查找和校验等实用功能",
        LogoText:   types.FckHelpLogo,
        UseChinese: true,
        Completion: true,
        RunFunc:    run,
        Notes: []string{
            "各子命令有独立帮助文档，可通过-h参数查看, 例如 'fck <子命令> -h' 查看各子命令详细帮助",
            "所有路径参数支持Windows和Unix风格",
        },
        SubCmds: []qflag.Command{
            HashCmd,
            SizeCmd,
            ListCmd,
            CheckCmd,
            FindCmd,
            PackCmd,
            UnpackCmd,
            PreviewCmd,
            WatchCmd,
        },
    }

    if err = qflag.ApplyOpts(rootCmdOpts); err != nil {
        err = fmt.Errorf("apply opts failed: %w", err)
        return err
    }

    if err = qflag.ParseAndRoute(); err != nil {
        err = fmt.Errorf("parse and route failed: %w", err)
        return err
    }

    return nil
}

func run(cmd qflag.Command) error {
    cmd.PrintHelp()
    return nil
}
```

func init() {
    HashCmd = qflag.NewCmd("hash", "h", qflag.ExitOnError)
    
    // 定义标志（从原来的commands/hash/flags.go移动过来）
    hashType = HashCmd.Enum("type", "t", "md5", "指定哈希算法，支持 md5、sha1、sha256、sha512", []string{"md5", "sha1", "sha256", "sha512"})
    hashRecursion = HashCmd.Bool("recursion", "r", false, "递归处理目录")
    hashWrite = HashCmd.Bool("write", "w", false, "将哈希值写入文件, 文件名为checksum.hash")
    hashHidden = HashCmd.Bool("hidden", "H", false, "启用计算隐藏文件/目录的哈希值，默认跳过")

    hashLocal = HashCmd.Bool("local", "l", false, "生成本地模式校验文件，记录绝对路径和基准目录")
    hashBasePath = HashCmd.String("base-path", "b", "", "指定基准路径(默认为当前工作目录)")
    
    cmdOpts := &qflag.CmdOpts{
        Desc: "文件哈希计算工具, 计算指定文件或目录的哈希值，支持多种哈希算法和并发处理",

### 6.2 导入路径调整

### 6.3 全局标志访问方式
有两种方案：

**方案1：保持全局变量**
```go
// internal/commands/hash/flags.go
package hash

import "gitee.com/MM-Q/qflag"

// 全局标志变量（保持不变）
var (
    hashCmdType      *qflag.EnumFlag
    hashCmdRecursion *qflag.BoolFlag
    // ...
)

// 在CLI层设置这些变量
func SetFlags(typeFlag *qflag.EnumFlag, recursionFlag *qflag.BoolFlag, ...) {
    hashCmdType = typeFlag
    hashCmdRecursion = recursionFlag
    // ...
}
```

**方案2：修改函数签名**
```go
// 修改业务逻辑函数签名，接收配置参数
func HashCmdMain(cl *colorlib.ColorLib, config *HashConfig) error {
    // 使用config中的参数
}

type HashConfig struct {
    Type      string
    Recursion bool
    Write     bool
    // ...
}
```

**推荐方案1**，因为改动更小，风险更低。
